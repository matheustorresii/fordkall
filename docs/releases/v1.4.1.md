# Ford Kall 1.4.1

- Corrige o failover que confundia uma API administrativa acessível com permissão de entrada na call. A função agora verifica a admissão RTC com um token assinado, sem abrir WebSocket, microfone, câmera ou sessão de mídia.
- A sonda verifica também o gateway `/rtc/v1` via HTTP sem Upgrade: em produção, o principal devolvia 200 em `/rtc/validate`, mas 429 no gateway de WebSocket. A resposta da validação não pode mais ocultar essa rejeição.
- A mesma checagem vale para projetos com credenciais diretas e para o token server/sandbox. O principal usava esse segundo caminho e antes escapava da checagem de disponibilidade das reservas.
- Projetos já tentados não se repetem na mesma entrada. Rejeições verificadas de cota, autorização ou indisponibilidade entram em cooldown; erros apenas do dispositivo não desabilitam globalmente um projeto saudável.
- Cotas, autorização, restrições regionais, falhas de servidor e erros locais têm diagnósticos separados. Restrições de região da sonda não impedem o SDK do usuário de encontrar sua região permitida.
- Mostra uma mensagem explícita de indisponibilidade quando nenhum projeto permite entrada, em vez de um erro interno genérico. O aviso não afirma que a cota acabou sem evidência.
- Preserva salas ocupadas e salas confirmadas cuja ocupação não pôde ser verificada, evitando dividir os participantes entre projetos. A liberação da rota verifica novamente sessões ativas para proteger a corrida entre uma conexão bem-sucedida e outra falha.
- Relatórios de uma tentativa são consumidos atomicamente. Novos diagnósticos persistem somente códigos e status HTTP; não armazenam tokens, URLs assinadas nem respostas brutas do provedor.

## Verificação e publicação

- `npm run test:sessions`: política de admissão, falhas de rede, região, privacidade e mensagens, além dos testes existentes de sessões/recuperação/desempenho.
- `npm run test:livekit:db`: migrações reais em PostgreSQL temporário, rotação sem repetição, pool indisponível, salas fixadas, corridas e permissões.
- `npm run test:livekit:live -- --linked`: teste opt-in da função publicada com uma conta e sala privadas temporárias, removidas ao final. Não abre mídia nem altera calls reais. Uma resposta explícita de indisponibilidade valida a detecção, não significa que a conexão foi restaurada. A opção adicional `--signaling` testa o upgrade de WebSocket apenas da conta/sala de QA e fecha imediatamente, sem áudio ou vídeo; não é usada pelo health check de produção.
- Aplicar `20261028000000_livekit_admission_failover.sql`, publicar a função `livekit-token`, validar o teste opt-in e publicar web/desktop/Android. Mantém o contrato para clientes anteriores.

A correção não cria franquia nem aumenta os limites do LiveKit. Se todos os projetos estiverem sem cota, sem autorização ou indisponíveis, ainda será necessário restabelecer capacidade válida. Credenciais e planos não são modificados por esta versão.
